# ADR-007: CQRS via @nestjs/cqrs, Separate Command and Query Handlers Per Context

## Status
Accepted

## Context
Order and inventory both have operations that mutate state (create order, reserve inventory) and operations that only read state (get order, get availability). Mixing these into a single service class blurs the distinction between "this changes something and needs a transaction, idempotency, and an outbox write" and "this just reads and needs none of that."

## Decision
Every mutation is a `Command` with exactly one `CommandHandler`; every read is a `Query` with exactly one `QueryHandler`, using `@nestjs/cqrs`'s `CommandBus`/`QueryBus`. Both extend shared base classes (`CommandBase`/`QueryBase`) from `libs/shared/kernel` carrying a `correlationId`. Command handlers follow a fixed shape: idempotency check, load/construct aggregate, open transaction, save plus outbox write, commit. Query handlers have no idempotency check, no transaction, and no outbox write, since they produce no side effects to deduplicate or record.

Apps register only the handlers relevant to their role: `order-capture` registers `CreateOrderHandler` and `GetOrderHandler` only; `order-orchestrator` registers `ConfirmOrderHandler` and `CancelOrderHandler` only, despite both apps sharing `libs/order/application`.

## Consequences
- The read/write distinction is structural (different base classes, different bus, different handler shape), not just a naming convention a developer could drift from.
- Selective handler registration per app (see ADR-001, ADR-003) is only possible because commands and queries are already separated at the library level; a single mixed `OrderService` class would not allow this per-app selectivity.
- Every handler is independently unit-testable in isolation with `Test.createTestingModule` and mocked ports, without needing a real HTTP or Kafka layer.
- Cost: more files (one command, one handler, one query, one handler, per operation) than a single service class would require. Judged acceptable given the system's stated learning goal and the structural benefits above.
